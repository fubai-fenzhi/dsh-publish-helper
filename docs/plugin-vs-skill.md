# DSH 插件 vs 技能：怎么选

> 一页判断：**动作进插件，流程进技能；能只做技能就不做插件。**

## 1. 两者是什么

| | 插件（bundle） | 技能（SKILL.md / runtime skill） |
|---|---|---|
| 本质 | 代码：注册工具、钩子、UI、HTTP 路由 | 文档：触发条件 + 步骤 + 坑 |
| 能执行动作 | ✅ 直接调 API / spawn / 写文件 | ❌ 只能教模型自己拼 shell |
| 常驻成本 | 工具 schema + 提示，**每轮都付费** | **0**（不命中不加载） |
| 加载成本 | 低（已常驻） | 命中一次约 500–800 token |
| 跨 agent | 仅 DSH | 任何 agent 都能读 |
| 安装 | 需安装 bundle | 复制文件即可 |
| 安全边界 | 代码里做默认值/校验/确认 | 只能"建议"，模型可能不听 |

## 2. 决策树

```text
要做的事需要「执行动作」吗？
├─ 否 → 只做技能（0 常驻成本）
└─ 是 → 这个动作使用频率高吗？
        ├─ 高（每轮都可能用） → 插件
        ├─ 低（偶尔用一次） → 技能 + 轻量 CLI，或 技能 + 插件（插件可禁）
        └─ 需要 UI/安全默认/复杂编排 → 插件
```

## 3. Token 账（关键）

| 方案 | 常驻/轮 | 用一次的成本 |
|---|---|---|
| 插件（3 个工具） | ~700–900 token | 工具调用输出 |
| 技能 | 0 | ~600 token（加载）+ 命令输出 |
| 技能 + 插件 | ~700–900 | ~600 + 调用 |

结论：
- **低频动作**（发视频、发版）→ 技能优先，插件按需启用
- **高频/必须自动触发**（报错钩子、记忆）→ 插件
- **不要把流程塞进插件描述**：描述只写"做什么/参数"，流程写进技能

## 4. 推荐模式：一套双形态

```text
your-plugin/
├── index.js          # 工具：原子动作（硬约束、安全默认）
├── lib/skill.mjs     # 技能：流程 + 坑（ctx.skills.register）
├── skills/           # 可选：给非 DSH agent 的 SKILL.md 副本
└── README.md
```

- 装插件 = 动作 + 技能一起到位
- 只装技能（复制文件）= 没有硬约束，但跨 agent
- DSH 里用 `ctx.skills.register()` 注册，零常驻

## 5. 判断清单

写代码前问：

- [ ] 这个动作必须由代码保证吗？（安全默认、校验、重试、API 签名）
- [ ] 模型每轮都会用到它吗？（是 → 插件，否 → 技能）
- [ ] 流程里有没有"绝对不能做"的步骤？→ 放进代码，不要只写文档
- [ ] 技能超过 2k 字了吗？→ 拆成多个技能或引用按需加载的文件
- [ ] 另一个 agent（Claude Code 等）也要用吗？→ 保留一份 `skills/` 文本

## 6. 常见错误

| 错误 | 后果 | 修法 |
|---|---|---|
| 把长流程写进插件系统提示 | 每轮付费，改一次要发版 | 移到技能 |
| 只做技能却需要安全默认 | 模型可能误操作 | 关键约束放插件 |
| 插件塞很多低频工具 | schema 常驻浪费 | 拆包或改成技能 + CLI |
| 技能里写"硬规则" | 模型可能忽略 | 代码里强制 |
| 技能互相引用大段文档 | 加载成本失控 | 只放步骤，细节按需读 |
